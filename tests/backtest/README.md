# Backtest

Бэктест-фреймворк на исторических данных (ТЗ §7): любое
изменение valuation прогоняется через бэктест и даёт сравнимый отчёт
(медианная ошибка, MAPE, распределение по коллекциям).

## Как это работает

`valuation/application/backtest.py` — `run_backtest`: walk-forward по
продажам без look-ahead. Для каждой продажи используются только продажи
строго раньше неё (+ пул активных листингов как floor-база). Ошибка —
относительное отклонение `|fair − actual| / actual` (MAPE на сделку);
итог — `BacktestReport` (медиана, среднее, массив ошибок, объяснимость,
вердикт по порогу, по умолчанию медиана ≤ 0.40).

## Гейт изменения модели

`valuation/application/model_gate.py` — `compare_models(baseline, candidate,
sales, active_listings, item_by_id, threshold, tolerance)`:

- гоняет обе модели по одним данным;
- возвращает `ModelComparisonReport`:
  - `delta` = медианная ошибка кандидата − baseline;
  - `promote` = кандидат сам проходит порог ошибки **и** не регрессирует
    относительно baseline более чем на `tolerance` (по умолчанию +5 п.п. MAPE);
  - `summary` — одна строка с обеими ошибками, дельтой и вердиктом
    (PROMOTE/REJECT) для CI-лога.

Использование перед деплоем: замените `candidate` на новую модель и
прогоните — отчёт сравним с любым другим прогоном по тем же данным.

Примеры: `tests/unit/test_backtest.py` (одиночный прогон) и
`tests/unit/test_model_gate.py` (сравнение: хуже/равно/пустые данные/логика
вердикта).
